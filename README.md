# Prayog (प्रयोग, "experiment")

Small-scale, controlled reproductions of key claims from well-known LLM fine-tuning, RL and systems papers.
Each experiment uses fixed seeds, several runs, reports mean ± std over seeds, and states plainly whether the
paper's claim **reproduced**, **partly reproduced**, or **did not reproduce**. Everything here runs on a laptop CPU;
GPU work lives separately in [`gpu/`](gpu/README.md) and is labelled by what has actually been run.

**Rule of the repo:** every number below comes from a saved `experiments/<name>/results.json`. The tables are
generated by `python scripts/build_cards.py`, which also produces each experiment's repro card
(`experiments/<name>/card.json`, shown in the dashboard). Verdicts are computed by a rule in that script.

## Run it

```bash
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python experiments/lora_vs_full/run.py              # add --smoke for a tiny CPU check
python experiments/distillation/run.py
python experiments/rl_ppo/run.py
python experiments/dpo/run.py                       # slow: downloads a 0.5B judge, judges 600 pairs
python scripts/build_cards.py                       # results.json -> card.json + README tables
uvicorn app.main:app --app-dir backend --port 8000  # API
cd frontend && npm ci && npm run dev                # dashboard on :5173 (proxies /api)
```

Docker: `docker compose up --build` serves the dashboard and API on http://localhost:8000 (MLflow UI on :5000).
Runs are also logged to MLflow (file store in `./mlruns`).

## PPO, GAE and the clipped objective, in my own words

Policy gradient asks: make actions that turned out better than expected more likely. "Better than expected" is the
**advantage**, `A_t = (what actually happened from t) − (what the value network predicted for s_t)`.
Using the full return gives an unbiased but very noisy advantage; using only a one-step estimate
`δ_t = r_t + γV(s_{t+1}) − V(s_t)` is low-noise but biased if `V` is wrong.
**GAE** blends the two: `A_t = δ_t + γλ δ_{t+1} + (γλ)² δ_{t+2} + …`, computed backwards in one pass.
`λ = 0` is the one-step estimate, `λ = 1` is the full return minus the baseline; 0.95 is a common middle.
Episode ends cut the sum so nothing leaks across episodes (`compute_gae` in `experiments/rl_ppo/ppo_scratch.py`).

Plain policy gradient can take one bad, huge step and wreck the policy. PPO reuses each batch for several epochs, so it
needs to stop the policy drifting from the one that collected the data. With `r = π_new(a|s) / π_old(a|s)`, the
**clipped objective** is `min(r·A, clip(r, 1−ε, 1+ε)·A)`. If an action was good (`A>0`), pushing its probability up
stops being rewarded once `r > 1+ε`; if it was bad, pushing it down stops being rewarded once `r < 1−ε`. The `min`
keeps the pessimistic of the two, so there is no gain from moving the policy far from where the data came from,
without needing a hard KL constraint.

## Honest limits

- Tiny models and small data (bert-tiny, pythia-70m, CartPole). These runs test whether a claim *shows up* at small
  scale, not whether the paper's headline numbers hold.
- The weights of the AI judge (Qwen2.5-0.5B-Instruct) are small; its labels are noisy. watsonx.ai Granite judge: adapter
  written in `prayog/judge.py`, **not run** (no key).
- LunarLander and the GRPO-style experiment were **not run**.
- GPU parts (Triton kernels, NCCL/DDP) are **not run**; there is no GPU on the dev machine and no GPU numbers are claimed.
- Live deployment is not part of this repo's history; see "Deploy".
